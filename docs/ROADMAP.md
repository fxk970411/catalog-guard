# Maintenance plan

This is a plan, not a claim of existing users or completed work.

1. Use the checker on one authorized real catalog. Keep private data out of the repository; turn discovered problems into fictional regression fixtures.
2. Publish 0.1.0 after the CI matrix passes. Review incoming issues weekly when possible; document fixes and release patches.
3. Invite a few relevant directory maintainers to try it, with permission and without unsolicited automated outreach. Record feedback only with consent.
4. Prioritize features from repeated problems: composite keys, field-specific severity, then streaming if dataset size warrants it.
5. Reassess whether this small tool adds value compared with established schema tools. Contribute upstream where that serves users better.

Evidence to collect honestly: released versions, reproducible fixes, public integration links, resolved issues, reviewed PRs, actual usage reports. Never manufacture stars, downloads, activity or testimonials. Continued maintenance matters even if no support grant is awarded.
